# 問3-1: 順序逆転・重複・遅延が頻発するイベントストリームからの結果整合性会計エンジン

**カテゴリ**: コーディング性 (高レイヤー)  
**配点**: 20点

## 課題設定

複数のマイクロサービスから非同期に届くドメインイベント (`AccountOpened`, `MoneyDeposited`, `MoneyWithdrawn`, `OverdraftLimitChanged`, `FeePolicyUpdated`, `TransactionReversed`) を受信し、各口座の **現在残高と手数料確定額を計算するステートマシン** を実装せよ。

アーキテクチャの整合性、複雑なドメインルールの不変条件維持、型システムによる安全性保証、および分散環境におけるエッジケースの排除能力を評価する。

## 制約条件

1. イベントはネットワークの都合上、発生時刻 (Logical Timestamp) とは無関係な順序で到着し、同じイベント ID が複数回届く (重複) ほか、`AccountOpened` より先に `MoneyDeposited` が届くケースがある。
2. 「残高が当座貸越枠 (OverdraftLimit) を下回った瞬間にペナルティ手数料が発生する」というルールがある。過去のタイムスタンプを持つ `MoneyDeposited` が遅れて到着した結果、「実は当時、当座貸越枠を下回っていなかった」と判明した場合、過去に遡ってペナルティ手数料を取り消し、それ以降のすべての残高推移と利子計算を **再評価 (Re-projection)** して補正イベントを発行しなければならない。
3. すでに外部へ確定通知 (`StatementFinalized`) された月次締め期間より前のタイムスタンプを持つ遅延イベントが到着した場合、過去の状態を直接書き換えず、**当月分の調整仕訳 (AdjustmentEntry)** として差額を計上すること。

## 採点基準 (20点)

- **8点**: 順序シャッフルおよび重複挿入を行った 1,000 件のイベントストリームをどのような順序で投入しても、全イベント投入完了後の最終残高・累計手数料が完全に同一の値 (決定論的収束) になる。
- **6点**: 月次締め境界をまたぐ遅延イベントが到着した際、確定済み期間のレコードが不変 (Immutable) に保たれたまま、当月期間での正確な差額調整トランザクションが生成される。
- **6点**: ドメインモデルとインフラ層が完全に分離されており、外部ライブラリに依存しない純粋な関数・メソッドとしてユニットテストが可能である。
