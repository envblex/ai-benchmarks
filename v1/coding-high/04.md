# 問3-4: 分散 Saga オーケストレーターにおける非同期タイムアウトと補償トランザクションの競合解決

**カテゴリ**: コーディング性 (高レイヤー)  
**配点**: 20点

## 課題設定

航空券予約、ホテル予約、レンタカー予約の 3 つの外部サービスを束ねる **Saga オーケストレーター** を実装せよ。各サービスの呼び出しは非同期で行われ、それぞれの補償トランザクション (キャンセル処理) が定義されている。

## 制約条件

1. あるステップ (例: ホテル予約) のリクエストがタイムアウトしたため、オーケストレーターがロールバックを開始した直後に、遅延していた「ホテル予約成功」のレスポンスが到着するケース (Timeout と Success の競合) が発生する。この場合、遅れて成功したホテル予約に対しても漏れなく補償トランザクション (ホテルキャンセル) を発行しなければならない。
2. 補償トランザクション自体がネットワークエラーで失敗する場合があるため、永続化された saga ログ (ステートストア) を用いて、プロセス再起動後にも未完了の補償処理を冪等に再開・完遂できるようにすること。
3. 同じ Saga インスタンスに対する並行イベント到着 (遅延レスポンスとタイマーイベントの同時発火) に対して、**楽観的ロック (Optimistic Concurrency Control)** またはバージョン番号を用いて状態の不整合を防ぐこと。

## 採点基準 (20点)

- **8点**: ネットワーク遅延・パケットロス・レスポンス順序逆転・オーケストレーター自身のプロセス強制再起動をシミュレートするカオステスト (100 パターン) において、最終的に「全予約が完了している」か「全予約がキャンセルされている」のどちらか一方の状態に 100% 収束する (部分予約状態の残留がゼロ)。
- **6点**: タイムアウト後に遅延成功レスポンスが届くエッジケースにおいて、予約が放置されず確実にキャンセル API が呼び出される。
- **6点**: 補償 API への呼び出しに一意な冪等キー (Idempotency Key) が付与されており、リトライ時に二重キャンセルエラーが発生しない (または正常終了として扱える)。
