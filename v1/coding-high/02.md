# 問3-2: 型システムを用いたプロトコル状態遷移とリソースリークのコンパイル時排除

**カテゴリ**: コーディング性 (高レイヤー)  
**配点**: 20点

## 課題設定

TypeScript (strict モード) または Rust を用いて、2 フェーズコミット (2PC) を伴うデータベース接続・トランザクション管理ライブラリの API および内部構造を実装せよ (Typestate Pattern の適用)。

## 制約条件

以下の不正な操作が記述された場合、実行時エラー (例外や `Result` の `Err`) ではなく、**必ずコンパイルエラー (型エラー)** として拒絶されるように型定義を構築すること。

1. 未接続 (`Disconnected`) または認証前 (`Unauthenticated`) の状態でクエリを発行する。
2. トランザクションを開始 (`Begin`) していない状態で `Prepare` や `Commit` を呼ぶ。
3. `Prepare` を呼ぶ前に `Commit` を呼ぶ、または `Prepare` 失敗後に `Commit` を呼ぶ。
4. 一度 `Commit` または `Rollback` したトランザクションオブジェクトを再利用してクエリを発行する。
5. 読み取り専用トランザクション (`ReadOnly`) として開始したコンテキスト内で、書き込み系クエリ (`Insert` / `Update`) のビルダーを渡す。

## 採点基準 (20点)

- **10点**: 用意された 15 個の「正しい使用例のテストコード」がすべてコンパイル成功し、15 個の「不正な状態遷移を含むテストコード」がすべてコンパイルエラー (TypeScript の場合は `@ts-expect-error` が成立すること、Rust の場合は `compile_fail` テストが通ること) になる。
- **6点**: `any` 型、型アサーション (`as unknown as ...`)、または `unsafe` ブロックによる型システムのバイパスを一切使用していない (静的解析で検査)。
- **4点**: ジェネリクスや Phantom Type (幽霊型) が適切に隠蔽されており、呼び出し側で冗長な型パラメータの手動指定を強制しない (型推論が自然に機能する)。
