# 実行環境・サンドボックス仕様

参照: `ok.pdf` p.12-13

## 1. 基盤インフラとリソース隔離 (全カテゴリ共通)

- 仮想化基盤: 1 問・1 試行 (Trial) ごとに、クリーンな初期スナップショットから起動する Firecracker MicroVM (または gVisor + cgroups v2 による厳密隔離コンテナ) を割り当てる。試行間の状態残留 (ファイル、共有メモリ、プロセス) は一切発生しない。
- ネットワーク遮断: 外部インターネットへのルーティングは完全に遮断 (エアギャップ化) する。カテゴリ 1 (Agent性) のみ、仮想ブリッジ経由で別コンテナ上のモック API 群 (`http://api.internal:8080` 等) への通信のみを許可する。
- 権限とシステムコール制限: 一般ユーザー権限 (`uid=1000 (agent)`, `sudo` 権限なし) のみを与える。また `seccomp-bpf` プロファイルにより、`ptrace` (他プロセスのメモリ検査)、`clock_settime` (システム時刻の改ざん)、カーネルモジュール操作を禁止する。

## 2. カテゴリ別の初期環境レイアウトとツールチェイン (要約)

| カテゴリ | サンドボックス初期状態・ディレクトリ構造 | リソース制限 |
|---|---|---|
| Agent性 | `/workspace` (作業用)、`/var/cache/packages` (オフラインパッケージ・パッチ群)、`/var/log/corrupted-db` (問 1-4 用バイナリログ)、`/data/corpus` (問 1-5 用メール・Wiki群)。モック API や復旧デーモンは AI からファイルやプロセスが見えない別 VM で稼働し、ソケットまたは HTTP のみで通信する。 | 仮想 CPU 2 コア、メモリ 4GB (ただし問 1-4 は `/dev/shm` を `size=16m` に制限)、ルート FS を read-only マウント (問 1-4) |
| コーディング性 (低レイヤー) | `/workspace/include` にインターフェース定義ヘッダ (変更不可・属性 `chattr +i`)、`/workspace/src` に実装テンプレート、`/workspace/tests/smoketest` に最小限の公開動作確認テストのみを配置。本番採点用のストレステスト・境界値テストはホスト側に秘匿する。 | 仮想 CPU 8 コア (問 2-1 の並行性検証用)、メモリ 4GB (動的設定: 問 2-2 実行時は `prlimit --as=65536` 等でヒープ 64KB 上限を OS 強制) |
| コーディング性 (高レイヤー) | `/workspace/spec` にドメイン型定義・インターフェース仕様、`/workspace/src` に実装ディレクトリを配置。外部パッケージマネージャ (`npm` / `cargo`) のレジストリ通信は遮断。 | 仮想 CPU 4 コア、メモリ 4GB、ディスク容量 1GB |
| 厳密論理推論・制約充足 | `/workspace/problemdata.json` に問題固有の数値パラメータ (問 4-3 の DAG およびタスク所要時間テーブル等) を配置。計算・探索補助としてローカル Python 環境および SMT ソルバー等の自作スクリプト実行を許可する。 | 仮想 CPU 4 コア、メモリ 4GB、1 問あたり実時間 15 分 (Python 3.12 標準ライブラリのみ。外部の専用ソルバーパッケージ `z3-solver` 等のインポートは禁止) |
| 情報統合・矛盾検出 | `/workspace/documents/` 配下に、問題ごとの生データ (問 5-1: 300 行の分散ログファイル群、問 5-2: 5 つの仕様書 Markdown、問 5-3: 10 ページの統計レポートと CSV データ、問 5-4: 6 つの契約書テキスト、問 5-5: 15 本の論文アブストラクト) を配置。 | 仮想 CPU 2 コア、メモリ 2GB、1 問あたり実時間 15 分 |
