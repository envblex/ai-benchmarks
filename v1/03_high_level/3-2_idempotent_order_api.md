# 問3-2：二重決済と在庫マイナスを防ぐ冪等（Idempotent）な注文APIの実装

## 1. 課題設定
同じ `Idempotency-Key` ヘッダを持つリクエストが複数回送信されても、絶対に二重決済や二重の在庫引き落としが発生しないAPIエンドポイントを実装せよ。

## 2. 制約条件
1. 同一キー＋同一ボディ: 前回レスポンスをそのまま返却。
2. 同一キー＋異なるボディ: `HTTP 422` または `409` エラー。
3. 同一キーの並行同時リクエスト: 2回目をブロックまたは排他制御。

## 3. 採点基準（20点満点）
* **8点**：同一キーのリトライ時に在庫が1回分しか減らず、決済モックが1回しか呼ばれない。
* **6点**：同一キーでパラメータを改変したリクエストに対して正しくエラーコードを返す。
* **6点**：レースコンディションテストでも二重決済が発生しない。
