# 問4-2: ビサンチン障害と通信遅延上限が混在する非同期合意プロトコルの反例トレース構築

**カテゴリ**: 厳密論理推論・制約充足  
**配点**: 20点

## 課題設定

7 つのノード (N1~N7) からなる分散システムにおいて、以下の独自合意アルゴリズムが提案されたとする。

### 提案されたアルゴリズム仕様

1. リーダー N1 が値 v ∈ {0,1} を全ノードにブロードキャストする。
2. 各ノードは最初に受信した値を自身の暫定値とし、`ECHO(v)` を全ノードに送信する。
3. あるノードが同じ値 v に対する `ECHO(v)` を 4 個以上受信したら、`VOTE(v)` を全ノードに送信する。ただし、すでに別の値で VOTE 済みの場合は送信しない。
4. あるノードが同じ値 v に対する `VOTE(v)` を 5 個以上受信したら、値 v を確定 (Commit) して停止する。

### 環境前提

- 最大 2 つのノード (N6, N7 とする) がビサンチン故障 (任意の異なるノードに異なる偽メッセージを送信可能) を起こしている。
- 残りの 5 ノード (N1~N5) は誠実 (Honest) だが、メッセージの到着順序はネットワーク遅延により任意に入れ替わる。

### 要求

このプロトコルには致命的な欠陥があり、

1. 「誠実なノード N2 が 0 を Commit し、別の誠実なノード N3 が一切 Commit せずに永久にデッドロックする (Liveness Violation)」、または
2. 「異なる値を Commit する (Safety Violation)」

の少なくとも一方が起こり得る。どちらの違反が成立するかを論理的に証明した上で、それを引き起こすステップバイステップのメッセージ送受信トレース (送信元、宛先、メッセージ種別、各ノードの内部状態の変化) を具体的に構築せよ。

## 採点基準 (20点)

- **6点**: Quorum Intersection (定足数の交差) の性質から、Safety Violation (異なる値の Commit) は起こり得ないことを数理的に証明している。
- **14点**: 提示されたメッセージ送受信トレースをシミュレータに入力した際、誠実ノードのアルゴリズム規約に一切違反することなく、実際に N2 が Commit 完了し、かつ残りの誠実ノードがいかなる後続メッセージを受信しても 5 個の VOTE を集められない状態に到達することが検証される。
- **6点**: Liveness Violation (一部の誠実ノードのみが Commit し他が永久にスタックする状態) が発生可能であることを正確に特定し説明している。
