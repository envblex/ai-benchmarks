# 問2-5: カスタムバイトコード VM における Mark-Sweep-Compact GC とルート探索の実装

**カテゴリ**: コーディング性 (低レイヤー)  
**配点**: 20点

## 課題設定

与えられたレジスタベースの簡易バイトコード命令セット (整数演算、構造体アロケーション、フィールド読み書き、関数呼び出し、クロージャ生成を含む) を実行する仮想マシン (VM) と、そのメモリを管理する **Mark-Sweep-Compact 方式** (断片化を解消するためにオブジェクトを移動させる) のガベージコレクタを実装せよ。

## 制約条件

1. ヒープ領域は **固定サイズの単一バイト配列 (1MB)** として割り当て、オブジェクトのヘッダ構造もその配列内に直接配置すること。
2. GC の Compaction (圧縮・移動) フェーズでヒープ内のオブジェクトのアドレスが変化した際、コールスタック上のローカル変数、レジスタ、および他オブジェクトのフィールドが保持している **すべてのポインタ参照を漏れなく新しいアドレスへ書き換えること** (ポインタのダングリング防止)。
3. 循環参照を含むオブジェクトグラフを正しく回収できること。

## 採点基準 (20点)

- **10点**: 合計 100MB 分の短命オブジェクトと長命オブジェクトを交互に生成し、かつ断片化を意図的に引き起こすテスト用バイトコードを実行した際、1MB のヒープ内で Compaction が正しく機能し、最後まで OOM を起こさず正しい計算結果を出力する。
- **6点**: GC 強制起動オプション (1 命令ごとに GC を実行するストレステストモード) を有効にした状態で実行しても、ポインタの更新漏れによるデータ破壊が一切発生しない。
- **4点**: 循環参照を持つ巨大グラフがルートから切り離された直後の GC サイクルで、1 バイトの漏れもなく空き領域として回収されている。
