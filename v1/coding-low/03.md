# 問2-3: 単一スレッド・非ブロッキング I/O によるゼロコピー HTTP/1.1 ルーターの実装

**カテゴリ**: コーディング性 (低レイヤー)  
**配点**: 20点

## 課題設定

Linux の `epoll` (または `io_uring`) システムコールを直接使用し、**10,000 本の同時接続を単一スレッド** で処理する HTTP/1.1 サーバーのコア部分を C または Rust (`libc` システムコール呼び出しのみ許可) で実装せよ。

## 制約条件

1. HTTP リクエストヘッダのパース時、受信バッファから別の文字列バッファへのメモリコピー (`memcpy`, `strdup`, `String` 生成) を **一切行わず**、受信バッファ内のオフセットと長さのスライス参照 (Zero-Copy) のみでルーティングとヘッダ抽出を行うこと。
2. パケットが細切れに到着する (1 バイトずつ `read` されるケースや、1 回の `read` でパイプライン化された 2 つのリクエストが同時に届くケース) 状態に **完全に対応** すること。
3. Slowloris 攻撃 (1 バイトずつ極めて遅く送信する接続) を検知し、他の正常な接続をブロックすることなく、該当接続のみをタイムアウト切断するタイマー機構を自前で実装すること。

## 採点基準 (20点)

- **8点**: チャンク分割送信・パイプラインリクエスト・不正な改行コードを含む意地悪なテストスイートに対して、クラッシュや状態破壊を起こさず正しくパース・応答できる。
- **6点**: AddressSanitizer (ASan) 下でバッファオーバーリードおよびメモリリークがゼロであり、リクエスト処理ループ内でヒープアロケーションが 0 回である。
- **6点**: 5,000 本の Slowloris 接続を維持した状態で、残りの 5,000 本の正常接続のレイテンシ劣化が 5% 未満に抑えられ、指定時間経過後に Slowloris 接続のみが正確にクローズされる。
