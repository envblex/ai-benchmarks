# 問2-2: ヒープ使用量 64KB 制限下での 10GB バイナリストリームの正確な 99 パーセンタイル算出

**カテゴリ**: コーディング性 (低レイヤー)  
**配点**: 20点

## 課題設定

標準入力から連続して流し込まれる **10GB のバイナリデータ** (IEEE 754 倍精度浮動小数点数 `double` の配列、ただし `NaN` と `±Inf` を含む) を読み込み、`NaN` と `±Inf` を除いた全有効データの **近似ではなく厳密な (Exact) 中央値および 99 パーセンタイル値** を出力するプログラムを C または Rust で実装せよ。

- 入力ストリームはシーク可能な 1 つの巨大ファイルとして与えられる (複数回のパス・シークは許可されるが、I/O 回数は最小化する必要がある)。

## 制約条件

1. プロセス全体の最大ヒープメモリ使用量を **64KB 以下** に制限する (`ulimit` またはカスタムアロケータで強制)。
2. 一時ファイルの作成を禁止する。
3. 実行時間はリファレンス環境 (NVMe SSD 上) で **2 パス分以内の I/O 時間 + CPU 処理時間** に収めること。

## 採点基準 (20点)

- **5点**: ファイルを読み込むパス回数が 2 回以下であり、システムコール回数を削減するため 64KB 制限内のバッファリング I/O を行っている。
- **5点**: 負の浮動小数点数における 2 の補数表現と符号・絶対値表現の順序逆転、および `-0.0` と `+0.0` の等価性をビット演算で正しく処理している。
- **10点**: 64KB のメモリ制限内で OOM を起こさず完走し、符号ビットおよび指数部・仮数部のビット表現を利用した **基数ヒストグラム (Radix Histogram / 2 パス目のバケット絞り込み)** によって、1 ビットの誤差もない正確な値を出力する。
