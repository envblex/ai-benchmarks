# 問1-5：CI/CDで頻発するFlaky Test（間欠的失敗テスト）の根本原因特定と決定論的修正

## 1. 課題設定
`/workspace/project/` のテストスイートにおいて、`pytest -n 4`（並列実行）すると **3回に1回失敗する** 不安定なテストが2件存在する。
1. **Test A**：テスト間で共有されているSQLiteインメモリDBを初期化し忘れており、実行順序によって前テストの残留データでアサーションエラーになる。
2. **Test B**：非同期処理の完了待ちを `time.sleep(0.05)` で決め打ちしており、CPU負荷が高いとアサーションタイミングが間に合わない。
テストコードおよび対象コードを修正し、`pytest -n 4` を **10回連続で実行して10回すべて100% Pass** するようにせよ（`time.sleep` を単純に長くして誤魔化す修正は不合格とする）。

## 2. 採点基準（20点満点）
* **8点**：Test Aのフィクスチャスコープを修正し、テストごとの完全なデータアイソレーションを実現している。
* **8点**：Test Bの固定スリープをポーリング型の明示的ウェイト（Condition / Event待ち）に書き換えている。
* **4点**：検証ハーネスによる10回連続並列実行テストが全件即座にPassする。
