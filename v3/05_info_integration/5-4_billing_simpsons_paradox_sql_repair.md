# 問5-4：複数データソース間の売上乖離（シンプソンのパラドックス）の定量的解明とSQL修正

## 1. 課題設定
日次売上集計バッチ（`/workspace/analytics/`）において、決済DBから算出したコンバージョン率と、アクセス解析ログから算出したコンバージョン率の推移が全体集計で逆転する「シンプソンのパラドックス（Simpson's Paradox）」が発生し、経営ダッシュボードの数値信頼性が失われている。
調査の結果、集計SQLにおいて「デバイス別（モバイル/PC）のトラフィック構成比の急激な変化」と「通貨換算レートの適用タイミング（注文時 vs 決済確定時）」が考慮されていない単純平均（AVG）が使われていることが判明した。
エージェントは統計的歪みの原因を特定し、正確な加重平均と通貨換算を行う分析SQLおよびデータマート生成スクリプトへ改修せよ。

## 2. 作業環境
- リポジトリ: `/workspace/analytics/`
  - 集計スクリプト: `aggregate_metrics.py`
  - 照合用DBダンプ: `data/metrics.sqlite`
- テストスイート: `pytest tests/test_analytics_reconciliation.py`

## 3. 達成条件
1. 2つのデータソース間でなぜ全体集計の逆転が生じているのか、サブグループ（セグメント）別の数値を比較して数理的要因を特定すること。
2. SQLクエリを改修し、加重平均（Weighted Average）およびセグメント調整済みレートを正確に算出するウィンドウ関数やCTE（共通テーブル式）を組み込むこと。
3. 照合テストを実行し、財務監査レポートの正解数値と100%一致させること。

## 4. 採点基準（20点満点）
* **8点**：シンプソンのパラドックスを引き起こしていた集計粒度および平均計算の統計的欠陥を正確に特定している。
* **6点**：SQLをリファクタリングし、パフォーマンスを維持しながら正確な加重平均計算を実装している。
* **6点**：Holdoutの異変トラフィックデータ（急激なデバイス比率変動データセット）に対しても正確な集計結果を出力する。
