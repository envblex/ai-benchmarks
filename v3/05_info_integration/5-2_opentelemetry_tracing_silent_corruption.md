# 問5-2：分散トレーシング（OpenTelemetry）ログからの非同期キューデータ化け箇所の特定と修正

## 1. 課題設定
数千スパンを含む分散トレーシングログ（JSONダンプ形式 `/workspace/traces/trace_dump.json`）と、3つの協調マイクロサービス（注文、配送、通知）のソースコードがある。
「特定条件下でユーザーの配送先住所の一部が空文字列に化ける」という本番不具合が発生しているが、例外エラーは一切ログに出ておらず、HTTPステータスも全サービスで200を返している（Silent Data Corruption）。
エージェントはトレーススパン間の属性（Span Attributes）、コンテキスト伝播（TraceContext / Baggage）、およびメッセージペイロードのシリアライズ差分を横断追跡し、データ破損を引き起こしているコードを特定・修正せよ。

## 2. 作業環境
- トレースデータ: `/workspace/traces/trace_dump.json`
- ソースコード群: `/workspace/services/`
- 再現テスト: `pytest tests/test_end_to_end_integrity.py`

## 3. 達成条件
1. トレースログを分析し、どのマイクロサービスのどの非同期処理ステップで属性値が欠落・書き換わっているかを特定すること。
2. 該当コードのオブジェクトディープコピー漏れ、または辞書の副作用による上書き箇所を修正すること。
3. E2Eテストを実行し、全スパンおよび最終メッセージペイロードのデータ完全性を証明すること。

## 4. 採点基準（20点満点）
* **8点**：トレースログから例外の出ないサイレントデータ破壊の発生コンテキストと原因コードを正確に特定している。
* **6点**：非同期処理におけるコンテキスト伝播およびペイロードのイミュータビリティを正しく修正している。
* **6点**：Holdoutトラフィック再現シナリオにおいて、データ欠損0件かつトレーシングスパンが完全な状態で完走する。
