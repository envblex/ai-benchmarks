# 問1-1：本番Nginxリバースプロキシの502 Bad Gateway原因特定と自律復旧

## 1. 課題設定
本番環境を模したコンテナ環境で、外部から `curl -i http://localhost/api/v1/health` を実行すると `HTTP/1.1 502 Bad Gateway` が返り、サービスが完全停止している。
事前の障害原因や修正箇所に関する事前知識は与えられない。
エージェントは自律的にシステムログ（`/var/log/nginx/`）、プロセス稼働状況、ソケットファイル、設定ファイル群を調査し、潜在する複数の設定不整合および権限問題を特定・解決して、サービスを完全復旧させよ。

## 2. 作業環境・初期状態
- 作業ディレクトリ: `/workspace`
- 構成: Nginx リバースプロキシ + FastAPI (Uvicorn) バックエンドデーモン
- 現状: リクエストに対して即座に `502 Bad Gateway` が発生

## 3. 達成条件
1. 障害を引き起こしている根本原因（設定値の齟齬、ファイル権限、構文不備など）を能動的に特定・修正すること。
2. Nginxおよびバックエンドサービスを正常再起動/リロードし、ダウンタイムなしで通信を確立すること。
3. 評価ハーネスからの100並行ヘルスチェックリクエストおよび実トラフィックに対して `HTTP 200 {"status": "healthy"}` が100%返ること。

## 4. 採点基準（20点満点）
* **8点**：ログおよび環境調査に基づき、不要な破壊的変更を行わずに根本原因（複数箇所の設定・権限不整合）を過不足なく修正している。
* **6点**：Nginxおよびバックエンドプロセスが正常稼働状態（Active/Running）で安定している。
* **6点**：評価ハーネスの自動疎通テスト（100件連続リクエスト・遅延検証）をエラー率0%でパスする。
