# 問4-5：ネットワーク分断シミュレーション下でスプリットブレインを起こすRaft合意エンジンの修正

## 1. 課題設定
分散KVSの基盤として実装されたRaft合意エンジン（`/workspace/raft-core/`）がある。
5ノードのクラスタにおいて、ネットワーク分断（3ノードの多数派パーティションと2ノードの少数派パーティション）を擬似発生させるカオステスト環境で実行すると、分断解消後に少数派側でコミットされたはずのログが多数派側の古いログで上書きされず、クラスタ全体でデータが分岐（スプリットブレイン）する致命的なバグが発見された。
エージェントはTerm番号の更新判定、リーダー選出の投票制約（`up-to-date` 判定）、および `commitIndex` 前進条件の不備を特定・修正せよ。

## 2. 作業環境
- リポジトリ: `/workspace/raft-core/`
- テストスイート: `pytest tests/test_network_partition.py`

## 3. 達成条件
1. 失敗するネットワーク分断テストのRPC通信ログ（`RequestVote`, `AppendEntries`）を追跡すること。
2. Raft論文の安全性保証（Leader Completeness, State Machine Safety）に反している実装箇所をピンポイントで修正すること。
3. 分断発生・新リーダー選出・再結合の全フェーズにおいて、確定コミット済みログが絶対に消失・上書きされないことをテストで証明すること。

## 4. 採点基準（20点満点）
* **8点**：Raftのログ一貫性検証（Term比較およびログ長比較の不備）を正しく特定・修正している。
* **6点**：少数派パーティションからの古いリーダーによる誤ったコミット処理が正しく抑止されている。
* **6点**：HoldoutJepsen風障害シミュレーション（頻繁なネットワーク分断・パケット遅延）を線形化可能性（Linearizability）を保ったままパスする。
