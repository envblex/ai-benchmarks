# 問4-4：PostgreSQLデッドロック多発トランザクション群のログ解析とロック順序一意化パッチ

## 1. 課題設定
高負荷トランザクション処理システム（`/workspace/db-tx/`）において、PostgreSQLのログに `ERROR: deadlock detected (SQLSTATE 40P01)` が秒間数十件記録され、大幅なロールバックと性能低下を引き起こしている。
システムには複数のワーカーから同時に呼び出されるバッチ処理・注文更新・在庫引当のトランザクションコードが存在する。
エージェントはDBログ（デッドロック検出グラフ）とPython側のDBアクセス層を突き合わせ、リソース（テーブルおよび行）へのロック獲得順序の非一貫性を特定し、大域的なロック順序（Lock Ordering Rule）に基づくパッチを適用してデッドロックを根絶せよ。

## 2. 作業環境
- リポジトリ: `/workspace/db-tx/`
- 再現テスト: `python3 tests/reproduce_deadlock.py`（並行実行で即座にデッドロック発生）

## 3. 達成条件
1. デッドロックログ内の待機関係（Process X waits for ShareLock on transaction Y, Process Y waits for ExclusiveLock...）を解析すること。
2. 該当する複数のクエリ発行箇所において、主キー順ソートによる行ロック取得（`SELECT ... FOR UPDATE ORDER BY id`）やテーブル走査順の統一を実施すること。
3. 並行度50での高負荷再現テストを実行し、デッドロック発生率0%およびデータ更新の整合性を実証すること。

## 4. 採点基準（20点満点）
* **8点**：デッドロックサイクルを形成していた複数のトランザクション処理の非対称なロック取得順序を正しく特定・修正している。
* **6点**：不要なテーブル全体ロックに逃げず、行レベルロックの順序正規化によって並行性能を損なわずに解決している。
* **6点**：Holdout高並行ストレステスト（100ワーカー同時実行）でデッドロック0件・トランザクション成功率100%を達成する。
