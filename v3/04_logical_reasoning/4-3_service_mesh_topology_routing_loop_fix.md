# 問4-3：サービスメッシュ障害ノード迂回ルーティングのトポロジー閉路・ブラックホール解消

## 1. 課題設定
動的サービスメッシュのトラフィックルーティングコントローラー（`/workspace/mesh-router/`）において、中間ノードがヘルスチェックに失敗した際に迂回経路を再計算するグラフアルゴリズムが組み込まれている。
しかし、複数の隣接ノードが同時に縮退運転モードに入った際、ダイクストラ法のコスト更新と分散ルーティングテーブルの反映タイミング差により、パケットが2つのノード間で無限往復する「ルーティングループ（Micro-loop）」または到達不能なデッドエンドへ吸い込まれる「ブラックホール」が発生する。
エージェントはグラフ更新ロジックにループ検出とポイズンリバース（Poison Reverse / Split Horizon的制御）を組み込んで修正せよ。

## 2. 作業環境
- リポジトリ: `/workspace/mesh-router/`
- トポロジーシミュレータ: `pytest tests/test_mesh_routing.py`

## 3. 達成条件
1. 複数ノード多重障害時のシミュレーションログをトレースし、TTL切れパケット破棄の原因となっている閉路を特定すること。
2. リンクステート更新時の収束アルゴリズムを修正し、過渡状態においてもループフリーな最短経路が選定されるようにすること。
3. 帯域幅制約を満たしつつ、疎通可能な全ノードへの通信到達率100%を保証すること。

## 4. 採点基準（20点満点）
* **8点**：多重ノード障害時におけるルーティングループおよびブラックホールの発生原因を根本修正している。
* **6点**：迂回時のリンクキャパシティ超過を起こさず、適切なフロー分散を実現している。
* **6点**：Holdoutの100ノード複雑トポロジー障害注入シミュレーションにおいてパケット到達率100%を達成する。
