# 問3-3：決済マイクロサービスにおけるネットワーク障害時のSaga補償トランザクション漏れ修正

## 1. 課題設定
注文・在庫引当・決済・ポイント付与の4サービスを跨ぐオーケストレーション型Sagaワークフロー（`/workspace/order-saga/`）がある。
障害注入テスト（Chaos Testing）環境において、「決済サービスへのHTTPリクエスト送信後、レスポンス受信直前にネットワーク分断（タイムアウト）」が発生した際、決済結果が不明なまま補償トランザクションが呼び出されず、在庫だけが引き当てられたまま注文がスタックする重大なデータ不整合が発生する。
エージェントは冪等リトライ（Idempotent Retry）およびタイムアウト時の状態判定・補償トリガーロジックを修正せよ。

## 2. 作業環境
- リポジトリ: `/workspace/order-saga/`
- カオステスト: `pytest tests/test_chaos_scenarios.py`

## 3. 達成条件
1. 失敗するカオステスト（ネットワークタイムアウト、500内部エラー、途中クラッシュ）のイベントログを解析すること。
2. 各ステップにおける未完了状態の永続化ログ（Saga Log）と、結果不明時の照会（Status Probe）＋補償アクション呼び出し機構を堅牢化すること。
3. 障害注入下でも、最終的に「全ステップ完了」または「全ステップ完全ロールバック（補償完了）」のいずれかの整合状態に収束させること。

## 4. 採点基準（20点満点）
* **8点**：結果不明タイムアウト時のステータス確認および補償トランザクションの未呼び出しバグを修正している。
* **6点**：各マイクロサービスへの補償リクエストが冪等に設計され、多重実行されても副作用が生じない。
* **6点**：Holdoutカオス障害スイート（パケットロス率30%およびサービス即時ダウン環境）でデータ不整合0件を達成する。
