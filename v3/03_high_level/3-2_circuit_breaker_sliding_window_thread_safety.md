# 問3-2：サーキットブレーカーのHalf-Open遷移時スレッドセーフティ不備と誤遮断修正

## 1. 課題設定
マイクロサービス間通信ライブラリ内のサーキットブレーカー（`/workspace/circuit-breaker/`）において、スライディングウィンドウ方式でエラー率を計算している。
`OPEN` 状態から `HALF_OPEN` に遷移して試験リクエストを送信する際、高並行リクエストが同時に `HALF_OPEN` を検知して大量のリクエストを一斉に外部へ流してしまうリーク問題と、古い時間バケットのメトリクスが適切にパージされずに直前のエラーを引きずって即座に `OPEN` へ逆戻りするバグが存在する。
エージェントはスライディングウィンドウのバケット管理と状態遷移アトミック性を修正せよ。

## 2. 作業環境
- リポジトリ: `/workspace/circuit-breaker/`
- テストスイート: `pytest tests/test_breaker.py`

## 3. 達成条件
1. マルチスレッド環境下での `test_half_open_probe_limit` および `test_sliding_window_eviction` の失敗原因を特定すること。
2. `HALF_OPEN` 状態における試験リクエストの同時実行数を設定値（例: 3件）に厳格に制限する同期機構を実装すること。
3. 時間経過に伴うスライディングウィンドウのクリーンアップを決定論的に動作させ、正常復旧テストをパスさせること。

## 4. 採点基準（20点満点）
* **8点**：`HALF_OPEN` 状態への遷移およびプローブ要求の同時実行数制限がアトミックに制御されている。
* **6点**：スライディングウィンドウバケットの古い統計情報が正しくパージされ、エラー率計算が正確に行われている。
* **6点**：Holdout並行耐障害テスト（高スレッド下での外部サービス障害・回復シミュレーション）をパスする。
