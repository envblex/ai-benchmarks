# 問3-4：多言語スキーマバリデータの再帰的依存フィールド評価時スタックオーバーフロー回避

## 1. 課題設定
複雑なJSON入力に対する動的バリデーションエンジン（`/workspace/schema-validator/`）がある。
フィールドAの許容値がフィールドBの値に依存し、フィールドBがフィールドCに依存するような「依存関係チェーン」をサポートしているが、循環依存（A -> B -> A）や、深さ1,000を超える深い階層のスキーマが入力された際、再帰呼び出しにより `RecursionError`（スタックオーバーフロー）でプロセスがダウンする。
エージェントは循環参照検出（DAGの閉路検知）と再帰探索の反復化（Iterative / Stack-based）を行い、多言語対応エラーツリーを安全に生成できるように改修せよ。

## 2. 作業環境
- リポジトリ: `/workspace/schema-validator/`
- テストスイート: `pytest tests/test_validation.py`

## 3. 達成条件
1. 失敗する循環依存スキーマテストおよび深層ネストテストをトレースすること。
2. スキーマコンパイル時に依存グラフのトポロジカルソートまたは閉路検出を行い、循環依存を明確なエラーメッセージとして弾くこと。
3. 評価フェーズを非再帰化し、10,000ノードの巨大スキーマに対してもメモリとスタックを安全に保ちながら検証を完了させること。

## 4. 採点基準（20点満点）
* **8点**：循環依存関係を安全に検知し、スタックオーバーフローを起こさずに適切なエラーを報告している。
* **6点**：再帰呼び出しをスタック/キューによる反復処理にリファクタリングし、深層スキーマでの安定稼働を実現している。
* **6点**：Holdoutスキーマテスト（数千件の複雑な相互依存定義）を高速かつメモリ安全に完走する。
