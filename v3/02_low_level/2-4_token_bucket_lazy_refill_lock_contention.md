# 問2-4：高並行トークンバケット型レートリミッターのロック競合ボトルネック解消

## 1. 課題設定
API Gatewayのインメモリレートリミッター（`/workspace/ratelimit/`）において、毎秒10万リクエストを超えるベンチマーク時に、トークン補充用バックグラウンドタイマーとリクエスト消費スレッドの間で激しいロック競合（Lock Contention）が発生し、CPU使用率が100%に張り付いてレイテンシが数十倍に跳ね上がる。
エージェントはタイマー駆動の補充方式を廃止し、アクセス要求時に経過時間からトークン数を計算する「Lazy Refill」アルゴリズムとアトミック操作（CAS）へのリファクタリングを行ってボトルネックを解消せよ。

## 2. 作業環境
- リポジトリ: `/workspace/ratelimit/`
- ベンチマークスクリプト: `python3 bench/run_bench.py`

## 3. 達成条件
1. ベンチマークプロファイル結果からミューテックス待機時間を特定すること。
2. Lazy Refill方式による遅延計算を導入し、バースト許容量（Capacity）および補充レート（Fill Rate）の計算精度を保ちながらロックフリーまたは細粒度ロックへ移行すること。
3. p99レイテンシを1/10以下に短縮しつつ、レートリミット判定の正確性テスト（指定上限を超えたリクエストの確実な遮断）をパスさせること。

## 4. 採点基準（20点満点）
* **8点**：Lazy Refillアルゴリズムを数学的・時間的に正しく実装し、タイマースレッドへの依存を排除している。
* **6点**：高並行アクセス時にもアトミックにトークン数が更新され、トークンの過剰消費（Leaky bucket）が起きない。
* **6点**：Holdout負荷ベンチマークにおいて目標スループット（100,000 ops/sec）およびp99レイテンシ要件を達成する。
