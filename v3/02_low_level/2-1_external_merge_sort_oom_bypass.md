# 問2-1：cgroupsメモリ制限（30MB）下での150MB CSVパイプラインOOM解消

## 1. 課題設定
大規模トランザクションCSV（100万行・約150MB）を集計・ソートするCLIバッチ（`/workspace/etl/`）が存在する。
本番コンテナのcgroups制限（メモリ上限30MB）を適用したテスト環境で実行すると、全件読み込み時に即座に `Killed`（OOM）で強制終了する。
エージェントはバッチコードを改修し、メモリ制限30MBを厳格に順守しながら、`score`（降順）→ `timestamp`（昇順）の複合ソート結果を正しくストリーム出力させよ。

## 2. 作業環境
- リポジトリ: `/workspace/etl/`
- 実行スクリプト: `bash run_with_limit.sh`（内部で `systemd-run` または `cgexec` による30MB制限付き実行）

## 3. 達成条件
1. 30MB制限下でOOMクラッシュすることを確認した上で、チャンク分割による外部ソート（External Merge Sort）パイプラインを実装すること。
2. 中間一時ファイルを適切にローテーションし、ディスク溢れを防ぎつつ、完了後にクリーンアップすること。
3. 全100万行のソート処理を30秒以内に完了させ、出力ファイルのハッシュ値が正解データと完全一致すること。

## 4. 採点基準（20点満点）
* **8点**：メモリ上限30MBのサンドボックス内でOOMを起こさずに完走する。
* **6点**：出力CSVの複合ソート順および行数が正解データと完全一致する。
* **6点**：規定時間（30秒）以内に処理が完了し、一時ファイルがすべて消去されている。
